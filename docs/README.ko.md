## 무엇인가

Di Carlo et al., *Dynamic Locomotion in the MIT Cheetah 3 Through Convex
Model-Predictive Control* (IROS 2018) 의 구현입니다. 13-상태 단일 강체 모델을
ZYX 오일러각 기준으로 선형화하고, 10-스텝 호라이즌 QP 를 OSQP 로 풀며,
Raibert 발판 계획과 베지에 스윙 궤적을 씁니다.

## 왜 플랜트가 두 개인가

**둘은 다른 질문에 답합니다.**

| | 묻는 것 |
|---|---|
| **SRB** (해석 모델) | 외부 변화 없이, 이 MPC 가 이 방정식에 대해 맞는가 |
| **MuJoCo** (물리 엔진) | 그 방정식이 실제 접촉·마찰·관절 동역학에서 얼마나 강인한가 |

한 클래스에 섞으면 실패했을 때 **어느 쪽이 틀렸는지 알 수 없습니다.**
그래서 `plants/plant_base.py` 에 인터페이스를 두고 구현을 둘로 나눴고,
러너에서 바뀌는 것은 한 줄입니다.

두 모델의 **의도된 차이 8 개를 코드로 선언**하고(`plants/model_audit.py`),
선언되지 않은 차이가 생기면 `UnexpectedModelMismatch` 를 던집니다. 마찰 제약은
MPC 가 사각뿔(선형), MuJoCo 가 타원뿔인데 — 이 차이를 지우지 않고 남긴 것이
실험의 내용입니다.

```
make run S=G_trot P=both      # 두 플랜트를 나란히
make view S=G_trot            # MuJoCo 뷰어로 재생 (macOS 는 mjpython)
make check                    # 물리 테스트 (~5 초)
```

trot 1 m/s · 4 초 실측:

| | SRB | MuJoCo |
|---|---|---|
| 평균 전진 속도 | 0.951 m/s | 0.870 m/s |
| roll/pitch RMS | 1.31° | 2.00° |
| 최대 관절 토크 | — | 146.5 N·m (한계 250) |

**두 열의 차이가 곧 선형화와 이상화의 대가입니다.** MuJoCo 가 느린 이유는
모델 감사가 그대로 설명합니다 — MPC 는 논문의 몸통 43 kg 만 알고 다리 질량을
모르므로 중력 보상이 6.6 % 모자랍니다. 여기에 SRB 에는 없는 관절 감쇠와
마찰, 체중에서 약 11 mm 가라앉는 연성 접촉이 더해집니다.

## 결함 13 개 — 이 저장소의 절반

돌아가는 코드였고 그림도 그럴듯했습니다. 계측과 테스트를 붙이자 결함 13 개가
나왔습니다. 셋만 옮깁니다.

**자세 운동학의 전치 누락.** `Θ̇ = R_z(ψ)ᵀ·ω` 여야 하는데 전치가 빠져
있었습니다. **ψ = 0 에서 두 식은 같습니다** — 직진 시나리오로는 영원히
재현되지 않습니다. 역기구학의 힙 부호 오류도 `y = 0` 근처에서 같은 방식으로
숨어 있었습니다(왕복 오차 0.16 m → 1.8e-16).

**접촉 판정과 지면반력의 시간 어긋남.** 접촉은 1 kHz, 힘은 30 Hz 로 계산해
공중에 뜬 다리에 최대 33 ms 동안 힘이 실렸습니다. 네 다리 중 둘이 0 이었던
것은 그 전이 시각이 우연히 MPC 격자에 정렬돼 있었기 때문이고, 로깅마저
30 Hz 라 **지연 자체가 로그에서 사라져 있었습니다.** 접촉은 이산 사건이라
고정 주기 표본화로는 지연이 반드시 남습니다 — 주기를 올리는 것은 줄일 뿐
없애지 못합니다. 이벤트 구동으로 바꿔 추가 연산 +6.7 % 에 잘못된 힘이
실리던 1,800 스텝을 0 으로, roll/pitch RMS 를 19.5 % 줄였습니다.

**스케일링 지수로 원인을 좁힌 사례.** 스윙 토크가 한계 250 N·m 를 넘어
273.8 이 나왔습니다. 게인 `ω_n` 을 두 배로 올리자 토크가 **네 배** —
`ω_n²` 입니다. 강성이 `ω_n²` 에 비례하므로 이는 "고정된 위치 오차 × 강성",
즉 **어딘가에 계단 입력이 있다**는 뜻이었습니다. 발판 목표가 MPC 주기로
갱신되고 있었고, 스윙 후반(위상 0.94)에서 19.7 mm 목표 점프가 0.11 ms 사이에
17.0 mm 지령 점프로 나타났습니다. 계획을 스윙 루프(1 kHz)로 옮기자 스케일링이
`ω_n¹` 로 돌아오고 토크는 92.9 N·m 가 됐습니다.

> 값의 크기보다 **값이 어떤 지수로 변하는가** 가 원인을 좁힙니다.

전체 13 개와 진단 방법은 [`defects.md`](defects.md) 에 있습니다. 목록이 아니라
**결함의 여섯 가지 형태**와 **형태를 좁히는 다섯 가지 측정**이 본문입니다.

## 재발을 막는 장치

테스트 **298 개**. 계층을 나눠 두었습니다.

| 계층 | 지키는 것 | 예 |
|---|---|---|
| 물리 불변량 | **구현과 독립적인 참** | 발이 지면을 뚫지 않음, 스윙 다리 힘 = 정확히 0 |
| 왕복 | 변환 쌍 | `FK(IK(p)) == p` |
| 골든 | 리팩토링 안전망 | 3 초 궤적, `rtol=1e-9` |
| 음성 대조군 | **측정 도구 자체** | 파라미터를 바꾸면 결과가 정말 바뀌는가 |

조용한 가정은 숫자로 노출합니다 — 스윙 위상 최대, yaw unwrap 스텝 최대,
이벤트 재해 횟수, **지지/스윙으로 나눈** 최대 토크. 마지막 것을 나눠 기록한
덕분에 위의 토크 결함을 찾을 수 있었습니다. 진단의 입도가 곧 대응의
해상도입니다.

골든 궤적의 재현성은 5 개 환경에서 측정했습니다 — macOS/arm64 와
Linux/x86-64, Python 3.11~3.13, OpenBLAS 와 Apple Accelerate. 모두
`rtol=1e-9` 에서 일치합니다. 다만 OSQP 버전이 전부 같으므로 **솔버 자체는
아직 변화시키지 않았다**는 한계를 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 에
함께 적었습니다.

## 아직 열려 있는 것

정직하게 남깁니다.

- 정상상태 전진 속도 오차 −4.9 % (`L_w_v` 와 `K_w_f` 의 균형)
- 스윙 제어에 `J̇q̇` 항이 없음
- `(3,1)` 과 `(3,)` 형상이 섞여 있음
- **마찰뿔 대각 미끄러짐** — galloping 에서 재봤으나 관측되지 않았다.
  다만 이것이 예측을 반증하지는 않는다. `‖f_xy‖/(μ·f_z)` 를 기록해
  명령된 힘이 원뿔 경계에 실제로 닿는지부터 재야 한다.
- **bound / gallop 의 초기 과도** — 정지 상태에서 체공 게이트를 시작한다.
  속도 지령이 계단이고, 저속에서는 Raibert 발판이 힙 바로 아래에 놓여
  가속할 지지점이 없다. 속도 램프 또는 게이트 전이가 필요하다.

자세한 것은 [`architecture.md`](architecture.md) 의 "아직 열려 있는 것".
